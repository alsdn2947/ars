# AI 에이전트

AI 에이전트는 LLM이 단순히 한 번 답변하고 끝나는 것이 아니라, **목표를 받아 스스로 계획하고, 도구를 사용하고, 결과를 확인하며 여러 단계를 반복해 작업을 완수하는 시스템**입니다.

## 챗봇과의 차이

| | 챗봇 | 에이전트 |
|---|------|----------|
| 동작 | 질문 1회 → 답변 1회 | 목표 → 계획 → 실행 → 검증 반복 |
| 도구 사용 | 없거나 제한적 | 검색, 코드 실행, 파일 조작, API 호출 등 |
| 자율성 | 낮음 | 중간 결과를 보고 스스로 다음 행동 결정 |

## 핵심 구성 요소

1. **LLM (두뇌)**: 상황을 판단하고 다음 행동을 결정합니다.
2. **도구 (Tools)**: 에이전트가 호출할 수 있는 함수들. 웹 검색, 코드 실행, DB 조회, 파일 읽기/쓰기 등. 각 도구는 이름·설명·파라미터 스키마로 정의되며, LLM이 설명을 읽고 언제 쓸지 판단합니다.
3. **루프 (Agent loop)**: "LLM이 도구 호출 결정 → 시스템이 도구 실행 → 결과를 LLM에 전달 → 다음 판단"을 목표 달성까지 반복합니다.
4. **메모리/컨텍스트**: 대화 이력과 중간 결과를 유지합니다. 긴 작업에서는 요약·외부 저장을 활용합니다.

## 도구 연동 표준: MCP

MCP(Model Context Protocol)는 LLM 애플리케이션과 외부 도구·데이터 소스를 연결하는 개방형 표준 프로토콜입니다. 도구 제공자가 MCP 서버를 한 번 만들어두면, MCP를 지원하는 어떤 에이전트에서도 그 도구를 쓸 수 있습니다.

## 설계 시 주의점

- **작게 시작**: 도구 2~3개짜리 단순한 루프로 시작해 필요할 때만 복잡도를 추가하세요.
- **도구 설명이 곧 성능**: LLM은 도구의 설명문을 보고 사용 여부를 판단하므로, 설명을 명확하게 쓰는 것이 중요합니다.
- **가드레일**: 파일 삭제, 결제 같은 위험한 행동에는 사람의 승인 단계를 넣으세요.
- **관측 가능성**: 에이전트가 어떤 판단으로 어떤 도구를 호출했는지 로그를 남겨야 디버깅이 가능합니다.
