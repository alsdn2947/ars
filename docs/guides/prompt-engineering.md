# 프롬프트 엔지니어링

프롬프트 엔지니어링은 LLM에서 원하는 결과를 안정적으로 얻기 위해 입력(프롬프트)을 설계하는 기술입니다.

## 기본 원칙

### 1. 명확하고 구체적으로

모호한 지시보다 구체적인 지시가 훨씬 좋은 결과를 냅니다.

```text
나쁨: 이 글 요약해줘
좋음: 이 글을 3문장 이내로 요약해줘. 대상 독자는 비전문가이고,
     기술 용어는 풀어서 설명해줘.
```

### 2. 역할 부여

모델에게 역할을 지정하면 답변의 관점과 톤이 일관되어집니다.

```text
당신은 10년차 백엔드 개발자입니다. 주니어 개발자가 이해할 수 있게
아래 코드의 문제점을 설명해주세요.
```

### 3. 예시 제공 (Few-shot)

원하는 출력 형식의 예시를 1~3개 보여주면 형식을 정확히 따릅니다.

```text
다음 형식으로 감정을 분류해줘.

입력: 오늘 정말 최고의 하루였어! → 긍정
입력: 별로였어. 다신 안 갈 듯 → 부정
입력: 음식은 맛있는데 서비스가 아쉬웠어 →
```

### 4. 단계적으로 생각하게 하기

복잡한 문제는 "단계별로 생각한 뒤 답하라"고 지시하면 정확도가 올라갑니다. 추론 과정을 먼저 쓰게 하고 결론을 마지막에 내게 하는 것이 요령입니다.

### 5. 출력 형식 지정

JSON, 마크다운 표, 목록 등 원하는 형식을 명시합니다. 프로그램에서 파싱할 거라면 "JSON 외의 텍스트는 출력하지 마세요"처럼 못박아 두는 것이 좋습니다.

## 구조화된 프롬프트 템플릿

실무에서는 아래처럼 섹션을 나눠 쓰면 관리하기 좋습니다.

```text
[역할] 당신은 ~입니다.
[작업] ~를 해주세요.
[제약] - 500자 이내
       - 존댓말 사용
[입력 데이터] """ ... """
[출력 형식] JSON: {"summary": ..., "keywords": [...]}
```

## 자주 하는 실수

- 한 프롬프트에 너무 많은 작업을 욱여넣기 → 작업을 나누는 편이 낫습니다.
- 부정형 지시만 쓰기("~하지 마") → 원하는 행동을 긍정형으로 함께 제시하세요.
- 프롬프트를 한 번 쓰고 끝내기 → 결과를 보고 반복적으로 개선하는 것이 기본입니다.
