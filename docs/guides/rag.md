# RAG (검색 증강 생성)

RAG(Retrieval-Augmented Generation)는 LLM이 답변을 생성하기 전에 **외부 지식 저장소에서 관련 문서를 검색해 프롬프트에 넣어주는** 기법입니다.

## 왜 필요한가

LLM은 학습 시점 이후의 정보를 모르고, 사내 문서 같은 비공개 데이터도 모릅니다. 또 아는 것도 [환각](../basics/what-is-llm.md)으로 틀리게 말할 수 있습니다. RAG는 이 문제를 "모델을 다시 학습시키지 않고" 해결합니다.

- 최신 정보, 사내 문서, 도메인 지식을 답변에 반영
- 근거 문서를 함께 제시할 수 있어 신뢰성 향상
- 파인튜닝보다 훨씬 저렴하고 즉시 갱신 가능

## 동작 흐름

```
사용자 질문
    │
    ▼
① 질문을 임베딩(벡터)으로 변환
    │
    ▼
② 벡터 DB에서 유사한 문서 조각(chunk) 검색
    │
    ▼
③ 검색된 문서를 프롬프트에 삽입
    │   "아래 문서를 참고해 질문에 답하세요: ..."
    ▼
④ LLM이 문서에 근거해 답변 생성
```

## 구축 단계

1. **문서 수집·전처리**: PDF, 위키, DB 등에서 텍스트를 추출합니다.
2. **청킹(Chunking)**: 문서를 검색하기 좋은 크기(보통 수백 토큰)로 자릅니다. 문단·섹션 단위로 자르는 것이 좋습니다.
3. **임베딩·색인**: 각 청크를 임베딩 모델로 벡터화해 벡터 DB(예: pgvector, Chroma, Qdrant 등)에 저장합니다.
4. **검색**: 질문과 유사도가 높은 청크를 상위 k개 가져옵니다. 키워드 검색(BM25)을 함께 쓰는 하이브리드 검색이 흔히 더 좋습니다.
5. **생성**: 검색 결과를 프롬프트에 넣고 "문서에 없는 내용은 모른다고 답하라"는 지시를 추가합니다.

## 품질을 높이는 요령

- **청크 크기 실험**: 너무 작으면 문맥이 끊기고, 너무 크면 노이즈가 섞입니다.
- **리랭킹(Re-ranking)**: 1차 검색 결과를 다시 정밀하게 순위 매기면 정확도가 올라갑니다.
- **출처 표기**: 답변에 어떤 문서를 근거로 했는지 인용하게 하면 검증이 쉬워집니다.
- **평가 셋 구축**: 대표 질문–정답 쌍을 만들어 검색·답변 품질을 계속 측정하세요.
